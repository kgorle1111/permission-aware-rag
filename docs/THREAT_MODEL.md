# Threat model

Every **controlled** or **accepted** row cites the check that pins it. `app/test_ledgers.py`
fails if a cited file or anchor disappears. **open** rows are known gaps, listed
so nobody mistakes silence for safety.

| T02 | Hidden doc shifts visible scores via corpus statistics | Visible-set BM25 stats; pgvector scores are per-row | `app/test_permission_rag.py` "S1: IDF side channel"; `app/run_evals.py` "def isolation_gate" | controlled |

| T12 | Edit or truncate the newest audit entry | JSONL chain checked against a separate local head checkpoint. pgvector checks stored line hashes AND, when `audit_checkpoint_path` is set, the newest row's id+hash against a file outside the database written after every audited call; deleting tail rows (even re-chaining the rest) or removing the file fails verification. Rewriting both store and checkpoint needs an independently retained head; the pgvector checkpoint is shared by app processes on one host (an exclusive `flock` on `<checkpoint>.lock` spans each audited call and each verification, and the file only moves forward from a head still present in the table, so a later call cannot heal a deleted tail); several hosts, or Windows, still need a shared anchor, and it is opt-in (unset = unanchored). The JSONL backend is safe for several app processes on one host: appends and verification hold an exclusive `flock` on `<log>.lock` (30 s bound, then fail closed), each append re-reads the file's real tail instead of an in-memory head, and it refuses to append unless that tail equals the checkpoint, so truncating the tail and carrying on cannot launder the log (Windows: thread-safe only). | T13 | SQL on the app connection grants itself ingest: forges `rag.mode` or writes chunks | Ingest is a separate DB role on its own connection; the app role has SELECT-only on chunks and no membership in the ingest role; setup REVOKEs legacy write grants | `app/test_pgvector.py` "def test_app_role_cannot_ingest_or_widen_visibility" | controlled |
| T14 | Signed JWT whose claims aren't valid principals (comma in a group forges an RLS principal; a bare-string `groups` iterates into characters) | `user_from_jwt` accepts only a non-empty `sub` and a list of non-empty group names without commas or whitespace; anything else is a 401 | `app/test_security.py` "def test_jwt_claims_must_be_valid_principals" | controlled |
| T15 | Aggregation: combining permitted docs to infer a forbidden fact | Retrieval ACLs cannot see this. Mitigation in the reference app only: each factual sentence of a drafted answer must cite a retrieved document, and sentences that do not are returned as `uncited_claims` for the reviewer. This checks citation coverage, not truth: a sentence can cite a permitted document and still combine facts into an inference. Human review remains the control | `app/test_claims.py` "def test_flags_each_sentence_without_a_retrieved_citation" | partly controlled |
| T16 | Formula execution when opening an audit CSV | Prefix dangerous cells with an apostrophe at export; source audit stays unchanged | `app/test_security.py` "def test_audit_csv_formula_injection" | controlled |
| T17 | Non-object JSON or invalid field types cause a request crash | Explicit body and query type checks; retrieval failures return 503 without results | `app/test_security.py` "def test_non_object_body_is_400"; `app/test_security.py` "def test_invalid_field_types_are_400"; `app/test_security.py` "def test_retrieval_error_is_503" | controlled |
| T18 | SQL on the app connection forges principals to widen what it can read | Principals reach RLS only as an HMAC-SHA256-signed, 60-second token verified inside Postgres by a SECURITY DEFINER function, with a key in a table neither app role can read; a raw `rag.principals` setting is ignored. Rotation (F5.3): tokens carry a key id inside the MAC; `rag_secret` holds a current key and an optional previous key that is accepted only until its grace deadline (at most 24 h); `rotate_principal_key` / `retire_previous_key` run as the schema owner and the key leaves only as the rotate call's return value | `app/test_pgvector.py` "def test_forged_principals_cannot_widen_visibility"; `app/test_pgvector_keys.py` "def test_old_key_works_during_grace_and_fails_after_retire"; `app/test_pgvector_keys.py` "def test_forged_tokens_are_rejected"; `app/test_pgvector_keys.py` "def test_app_role_cannot_read_keys" | controlled (a stolen key stays valid until rotated and retired; rotation is manual, there is no scheduler) |
| T19 | SQL on the app connection runs unaudited reads, appends forged audit entries, or reads audit metadata | The app role has no SELECT on chunks and no INSERT on audit; every read goes through `rag_search`, a SECURITY DEFINER function owned by a NOLOGIN, non-BYPASSRLS role, which verifies the signed token, applies RLS and writes the hash-chained audit row server-side with exactly the ids it returned. Reading audit metadata (user ids, returned chunk ids, no query text) remains: the app needs SELECT on audit for its `/audit` view | `app/test_pgvector.py` "def test_app_role_can_only_search_through_the_audited_function" | controlled for unaudited reads and forged entries; metadata reads accepted |
| T20 | Cost exhaustion: a caller drives the paid LLM call without bound | Per-IP rate limit on `/ask` (reference app); a UTC-day spend cap (`DAILY_BUDGET_USD`) skips the LLM and returns retrieval-only results once projected spend would pass it. The cap is a reservation: the projected worst case is held atomically before the call (SQLite `BEGIN IMMEDIATE`, shared by all server processes on one host) and swapped for the actual cost after, so concurrent calls cannot overshoot; a crashed holder's reservation expires after 5 minutes. One host only: a second host keeps its own file (B13) | `app/test_obs.py` "def test_at_budget_exactly_still_calls_llm_and_over_skips"; `app/test_obs.py` "def test_concurrent_asks_cannot_overshoot_the_cap"; `app/test_ops_store.py` "def test_concurrent_reservations_never_pass_the_cap"; `platform/tests/test_observability.py` "def test_at_budget_calls_model_and_over_budget_skips_with_note" | controlled on one host (hard cap); the per-IP rate limit is still per process (B03) |
| T21 | Request logs leak query, answer or document text (PII) | Log records are built from ids, counts and timings only; exception messages are reduced to their class name in the reference app. Stack traces from dependencies in the platform are not scrubbed | `app/test_obs.py` "def test_canary_query_appears_in_no_log_record_on_any_path"; `platform/tests/test_observability.py` "def test_canary_query_appears_in_no_log_record_on_any_path" | partly controlled |

| T23 | Reranker is handed (or scores) text the caller cannot read | The reranker input is only the engine-filtered hit list; the cross-encoder scores each pair independently; a reranker failure falls back to vector order and marks the response degraded | `platform/tests/test_retrieval_models.py` "def test_reranker_only_receives_acl_filtered_candidates"; `platform/tests/test_retrieval_models.py` "def test_reranker_failure_falls_back_to_vector_order_and_marks_degraded" | controlled |
| T24 | A shared embedding cache lets one user's query speed up another's (who-asked-what timing signal) | The cache serves the document (ingest) path only; query embedding never reads or writes it | `platform/tests/test_retrieval_models.py` "def test_query_path_never_reads_or_writes_the_cache" | controlled |
| T25 | An LLM-written SQL statement (hostile model, or a prompt-injected question) reads rows or tables the caller may not, writes, escapes its role, stalls the audit chain, or runs unaudited; aggregates (`count`, `sum`, `min`) over metadata include hidden rows (the T15 shape, for structured data) | The statement runs inside `rag_sql_run`, which verifies the signed token (T18), executes `rag_sql_exec` as `rag_sql` (NOLOGIN, non-BYPASSRLS, not the table owner, no SET ROLE to undo), and writes the hash-chained audit row itself with hashes and status, never text (T19 pattern). `rag_sql` can read only the non-ACL columns of `doc_meta`, whose RLS policy uses the same signed principals; the statement opens as a cursor (exactly one query), under `transaction_read_only`, a 2 s `statement_timeout` and a 100-row cap; session advisory locks are released. The app's pre-check is defence in depth: the adversarial suite bypasses it | `app/test_text_to_sql.py` "def test_hostile_sql_errors_or_returns_only_visible_rows"; `app/test_text_to_sql.py` "def test_aggregates_count_only_visible_rows"; `app/test_text_to_sql.py` "def test_metamorphic_hidden_rows_never_change_a_low_privilege_result"; `app/test_text_to_sql.py` "def test_every_attempt_is_audited_by_the_database_without_text" | controlled for the 40 hostile statements and the aggregates tested; residuals accepted: `pg_class.reltuples`/`pg_stat_*` expose the table's total row estimate to any role (B15), and `doc_meta` visibility is document-level only (B14) |
